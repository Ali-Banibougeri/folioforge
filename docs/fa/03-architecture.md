# ۰۳ — وب‌سایت از نظر فنی چگونه کار می‌کند؟

[← راهنمای اصلی](../../README.fa.md) · [English](../en/03-architecture.md)

FolioForge صفحه رزومه را ایستا نگه می‌دارد. بنابراین میزبانی سریع، ارزان و ساده است و عامل کدنویسی می‌تواند آن را راحت‌تر شخصی‌سازی کند. آرکید اختیاری برای شمارنده مشترک و ثبت امتیاز تأییدشده از API استفاده می‌کند.

## بخش مرورگر

- HTML بخش‌های معنایی و کنترل‌های قابل‌دسترس را تعریف می‌کند.
- CSS در starter/site/assets/styles.css سیستم طراحی، واکنش‌گرایی، چاپ و تنظیم RTL را مشخص می‌کند.
- فایل starter/site/assets/portfolio-data.js محتوای رزومه به فارسی و انگلیسی و رنگ‌های تم را نگه می‌دارد.
- اسکریپت starter/site/assets/site.js بخش‌های تجربه، پروژه، مهارت، تحصیلات و تماس را با گره‌های متنی DOM می‌سازد. این روش باعث می‌شود متن رزومه به‌عنوان HTML اجرایی تفسیر نشود.
- صفحه آرکید موتور چهار بازی و کنترل‌ها را دارد.
- کلاینت API فقط درخواست عمومی می‌فرستد و کلید محرمانه سمت سرور ندارد.

## چرا محتوا از ساختار جدا شده است؟

عامل کدنویسی باید بتواند تجربه و پروژه‌های شما را عوض کند، بدون اینکه ساختار صفحه را از نو بنویسد. این کار نگهداری را ساده‌تر می‌کند و به افراد غیربرنامه‌نویس نشان می‌دهد اطلاعات خودشان کجا قرار می‌گیرد.

تاریخ، عنوان، نام و لینک واقعی وارد کنید. اگر چیزی معلوم نیست، آن را خالی بگذارید یا تا زمان بررسی با جای‌خالی واضح مشخص کنید.

## تغییر زبان

داده رزومه بخش‌های جداگانه en و fa دارد. نمایشگر صفحه زبان و جهت سند را تغییر می‌دهد و سپس محتوای همان زبان را رسم می‌کند. انگلیسی LTR و فارسی RTL است. در متن ترکیبی، نام پروژه، URL، ایمیل و نام فناوری باید قابل خواندن بمانند.

آرکید هم لایه ترجمه کوچکی دارد. هنگام تغییر پیام‌های پویا مطمئن شوید پس از فریم بعدی، تغییر امتیاز یا شروع دوباره، زبان انتخاب‌شده حفظ می‌شود.

## بک‌اند اختیاری

برای نمایش رزومه به بک‌اند نیاز نیست. اگر فعال شود:
۱. مرورگر نوع عملیات و داده‌ها را به تابع Edge می‌فرستد.
۲. تابع Edge مبدأ، کلید عمومی، ساختار درخواست و محدودیت نرخ را بررسی می‌کند.
۳. خواندن یا نوشتن دارای مجوز در سرور و با کلید محرمانه سرور انجام می‌شود.
۴. RLS فعال است و مجوز نوشتن مستقیم عمومی مسدود شده است.
۵. امتیاز بازی تنها پس از بازپخش ورودی‌ها با seed ایجادشده در سرور پذیرفته می‌شود.

کلید قدرتمند سرور نباید به مرورگر برسد. تنظیمات عمومی جایگزین مجوز دیتابیس نیستند.

## انتشار استاتیک

گردش‌کار GitHub Actions فقط starter/site را به GitHub Pages می‌فرستد. مستندات، کد تابع سرور و راهنمای تنظیمات داخل مخزن می‌مانند و جزو خروجی عمومی سایت نمی‌شوند.

GitHub Pages کد سمت سرور را اجرا نمی‌کند. قابلیت‌های اختیاری سرور در Supabase Edge Functions اجرا می‌شوند.

## چطور تغییر را امن انجام دهیم؟

۱. فایل مرتبط و رفتار فعلی را بخوان.
۲. کوچک‌ترین تغییر درست را اعمال کن.
۳. هر دو ترجمه را به‌روزرسانی کن.
۴. node scripts/check.mjs را اجرا کن.
۵. تغییر را در مرورگر و اندازه موبایل و دسکتاپ بررسی کن.
۶. اگر قوانین بازی تغییر کرده‌اند، بازپخش سرور را هم تغییر بده.
۷. پیش از commit تمام فایل‌های جدید را از نظر اطلاعات شخصی و کلید محرمانه بررسی کن.
