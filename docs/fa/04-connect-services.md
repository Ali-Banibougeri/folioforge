# ۰۴ — اتصال حساب‌ها و ابزارها، بدون حدس و گمان

[← راهنمای اصلی FolioForge](../../README.fa.md) · [English](../en/04-connect-services.md)

این راهنما می‌گوید چه زمانی حساب لازم است، چه چیزی را باید وصل کنید و عامل هوش مصنوعی کدام مجوزها را نباید خودسرانه فرض کند. برای شروع ساخت رزومه لازم نیست همه حساب‌ها را ایجاد کنید.

## به کدام سرویس‌ها نیاز دارم؟

| هدف | لازم است | اختیاری |
|---|---|---|
| ساخت و پیش‌نمایش رزومه روی رایانه | نسخه‌ای از مخزن و ویرایشگر یا محیط AI دارای دسترسی ویرایش فایل | حساب GitHub |
| ویرایش مستقیم فایل توسط ChatGPT/Codex | محیطی که ویرایش فایل محلی را پشتیبانی کند؛ هنگام درخواست، اتصال ابزار را تأیید کنید | اتصال GitHub اگر روی Clone محلی کار می‌کنید |
| قرار دادن سورس در GitHub | حساب GitHub و اجازه ساخت/ارسال به مخزن | GitHub CLI |
| انتشار آنلاین رزومه | مخزن GitHub و مجوز GitHub Pages یا یک میزبان دیگر | دامنه اختصاصی |
| نمایش شمارنده مشترک بازدید | حساب/پروژه Supabase، اجرای SQL، کلید publishable و تابع Edge منتشرشده | اصل قابلیت شمارنده |
| نمایش رزومه بدون شمارنده | هیچ حساب اضافی لازم نیست | Supabase |

صفحه رزومه ایستا است. فقط به دلیل وجود نام Supabase در پروژه، حساب ایجاد نکنید؛ تنها اگر شمارنده مشترک می‌خواهید به آن نیاز دارید.

## الف. GitHub: ساخت حساب و مخزن

۱. به https://github.com/signup بروید، حساب بسازید و ایمیل را تأیید کنید.

۲. از https://github.com/login وارد شوید.

۳. با دکمه New repository مخزن خودتان را بسازید. نام دلخواه انتخاب کنید. مخزن را فقط زمانی Public قرار دهید که آماده انتشار محتوایش هستید؛ در غیر این صورت Private انتخاب کنید.

۴. اطلاعات خصوصی رزومه را پیش از آماده بودن برای انتشار، در مخزن عمومی قرار ندهید.

۵. اگر ابزار هوش مصنوعی به GitHub متصل می‌شود، اتصال رسمی/Sign in را باز کنید و فقط دسترسی‌هایی را تأیید کنید که آن‌ها را می‌فهمید.

۶. اگر ابزار اجازه push کردن commitها را ندارد، از محیط ویرایش فایل محلی استفاده کنید و نتیجه را خودتان push کنید.

خصوصی یا عمومی بودن مخزن با خصوصی یا عمومی بودن سایت فرق دارد. قبل از خصوصی کردن مخزن سورس، راهنمای انتشار را بخوانید؛ در GitHub Free مخزن سایت کاربری Pages باید عمومی باشد.

## ب. ChatGPT یا عامل کدنویسی: محیط مناسب را وصل کنید

دو حالت رایج وجود دارد:

### کار با پوشه محلی

۱. مخزن را Clone یا دانلود کنید.

۲. پوشه پروژه را در محیط هوش مصنوعی‌ای باز کنید که اجازه خواندن و ویرایش فایل‌ها را دارد.

۳. رزومه را پیوست کنید.

۴. دستور شروع README.md را بفرستید.

۵. اجازه دهید عامل فایل‌ها را تغییر دهد و node scripts/check.mjs را اجرا کند.

اگر ابزار فقط می‌تواند در چت پاسخ دهد و امکان ویرایش فایل ندارد، باید شفاف بگوید و ZIP کامل یا patchهای دقیق فایل‌به‌فایل تحویل دهد؛ نباید ادعا کند رایانه شما را تغییر داده است.

### کار با اتصال GitHub

۱. بخش رسمی Connect/Integrations ابزار AI را باز کنید.

۲. GitHub را انتخاب کنید، وارد شوید و دسترسی مخزن را تأیید کنید.

۳. اگر ابزار پرسید، مخزن FolioForge را از میان مخزن‌های مجاز انتخاب کنید.

۴. از عامل بخواهید ابتدا مخزن را بررسی کند و پیش از commit کردن، امکان خواندن/نوشتن را تأیید کند.

رمز GitHub یا personal access token را در چت نفرستید. اگر ابزار می‌گوید دسترسی ندارد، خودتان روند رسمی تأیید مجوز را کامل کنید.

## ج. Supabase: فقط برای شمارنده حساب بسازید

۱. به https://supabase.com/dashboard/sign-up بروید و حساب بسازید یا وارد شوید.

۲. روی New project بزنید و سازمان خود را انتخاب کنید.

۳. نامی قابل تشخیص و رمز قوی دیتابیس انتخاب کنید. رمز را در password manager ذخیره کنید.

۴. منطقه مناسب را انتخاب و منتظر آماده شدن پروژه بمانید.

۵. در SQL Editor فایل starter/backend/visitor-counter-schema.sql را اجرا کنید.

۶. در بخش Connect/API Keys، URL پروژه و کلید publishable را بردارید.

۷. فقط URL و کلید publishable را در starter/site/assets/site-config.js قرار دهید.

۸. در Edge Functions → Secrets مقدار FOLIO_SITE_ORIGIN را برابر مبدأ سایت عمومی و VISITOR_RATE_SALT را برابر یک مقدار تصادفی طولانی قرار دهید. salt و کلید سرور را در فایل مرورگر نگذارید.

۹. فایل starter/backend/functions/visitor-counter/index.ts را با نام visitor-counter منتشر کنید.

۱۰. بررسی کنید درخواست بازدید پاسخ ok: true و یک عدد برمی‌گرداند.

راهنمای کامل‌تر در starter/backend/README.md و docs/fa/05-security-publishing.md قرار دارد.

## د. اعلان اتصال

هنگام اجرای محلی، اگر شمارنده بازدید تنظیم نشده باشد، صفحه رزومه یک اعلان کوچک راه‌اندازی نشان می‌دهد. همچنین می‌توانید ?setup=1 را به انتهای آدرس اضافه کنید تا اعلان عمداً نمایش داده شود. این پیام به بازدیدکنندگان عادی سایت عمومی نمایش داده نمی‌شود.

اعلان به صفحه ساخت حساب Supabase و راهنمای اتصال لینک می‌دهد و از بازدیدکننده رمز یا کلید نمی‌خواهد. این فقط یادآوری برای کسی است که پروژه را تنظیم می‌کند.

## ه. وقتی اتصال موجود نیست، عامل باید چه کند؟

عامل درست باید:

۱. سرویس موردنیاز و دلیل نیاز را مشخص کند.
۲. لینک رسمی ثبت‌نام یا تأیید مجوز را بدهد.
۳. حداقل سطح مجوز لازم را توضیح دهد.
۴. روشن کند آیا کار بدون آن اتصال ادامه‌پذیر است یا نه.
۵. کارهایی را که وابسته به اتصال نیستند ادامه دهد.
۶. در اقدام نیازمند مجوز، منتظر تأیید صریح کاربر بماند.
۷. ادعا نکند حساب ساخته شده، کد push شده یا تابع منتشر شده مگر واقعاً بررسی شده باشد.

## خطاهای رایج

- **شمارنده همچنان — است:** URL/کلید عمومی تنظیم نشده یا تابع سرور منتشر نشده است.
- **origin_not_allowed:** مقدار FOLIO_SITE_ORIGIN باید دقیقاً برابر مبدأ سایت باشد؛ شامل scheme و host، بدون مسیر.
- **rate_limit_not_configured:** VISITOR_RATE_SALT را در Edge Function Secrets بسازید.
- **invalid_api_key:** کلید publishable در site-config.js را بررسی کنید.
- **URL سایت Pages وجود ندارد:** در Settings → Pages منبع GitHub Actions را انتخاب و لاگ‌های workflow را بررسی کنید.

کلیدهای محرمانه را در گزارش خطا ارسال نکنید. فقط کد/پیام خطا را پس از حذف اطلاعات خصوصی به اشتراک بگذارید.
