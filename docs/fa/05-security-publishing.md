# ۰۵ — امنیت، شمارنده بازدید و انتشار

[← راهنمای اصلی](../../README.fa.md) · [English](../en/05-security-publishing.md)

## میزبانی ایستای رزومه

رزومه از HTML، CSS، JavaScript و تصویر تشکیل شده است و برای نمایش به دیتابیس یا کلید محرمانه نیاز ندارد. GitHub Pages فایل‌های ایستا را میزبانی می‌کند؛ کد بک‌اند را اجرا نمی‌کند.

گردش‌کار .github/workflows/deploy-pages.yml فقط starter/site را منتشر می‌کند. مستندات و تابع سرور در مخزن سورس می‌مانند.

## حساب GitHub و Pages

۱. در https://github.com/login وارد شوید یا از https://github.com/signup حساب بسازید.

۲. مخزن شخصی خودتان را ایجاد کنید یا در صورت فراهم بودن از قالب استفاده کنید. رزومه شخصی را پیش از آماده بودن برای انتشار، در مخزن عمومی قالب قرار ندهید.

۳. پروژه را به مخزن خودتان ارسال کنید.

۴. به Settings → Pages بروید و GitHub Actions را به عنوان منبع انتشار انتخاب کنید.

۵. آخرین اجرای workflow را بررسی کنید و URL سایت را باز کنید.

ممکن است عامل کدنویسی نیاز داشته باشد که اتصال GitHub را تأیید کنید یا پوشه Cloneشده را در محیطی باز کنید که اجازه ویرایش فایل دارد. پیش از رسیدن به این مرحله، باید اطلاع دهد چه اتصال یا مجوزی لازم است و مسیر دقیق ورود/مجوزدهی را توضیح دهد. رمز یا token را در چت نخواهد.

## شمارنده بازدید اختیاری با Supabase

Supabase فقط برای شمارنده مشترک لازم است. برای فعال‌سازی:

۱. از https://supabase.com/dashboard/sign-up حساب بسازید.

۲. یک پروژه جدید Supabase ایجاد کنید.

۳. فایل starter/backend/visitor-counter-schema.sql را در SQL Editor پروژه اجرا کنید.

۴. URL پروژه و کلید publishable را در starter/site/assets/site-config.js قرار دهید.

۵. starter/backend/config.toml را با شناسه پروژه خودتان تنظیم کنید.

۶. در Edge Functions → Secrets مقدار VISITOR_RATE_SALT را به یک مقدار تصادفی طولانی و FOLIO_SITE_ORIGIN را به مبدأ دقیق سایت تنظیم کنید.

۷. تابع visitor-counter را از starter/backend/functions/visitor-counter/index.ts منتشر کنید.

۸. پاسخ تابع و شمارنده نمایش‌داده‌شده را تست کنید.

جزئیات ساخت حساب در [۰۴ — اتصال حساب‌ها و سرویس‌ها](./04-connect-services.md) آمده است. اگر Supabase تنظیم نشده باشد، شمارنده نباید رزومه را از کار بیندازد.

## امنیت کلیدها

- کلید publishable برای مرورگر طراحی شده است اما جایگزین امنیت دیتابیس نیست.
- کلید secret یا service-role را در HTML، JavaScript مرورگر، مخزن عمومی، تصویر یا پیام قرار ندهید.
- credential دارای دسترسی بالا را در مدیریت امن اسرار Supabase نگه دارید. تابع از map محرمانه داخلی Supabase استفاده می‌کند؛ در صورت نیاز می‌توان FOLIO_COUNTER_SECRET_KEY را فقط در Edge Function Secrets تنظیم کرد.
- Row Level Security را فعال نگه دارید.
- مجوز insert، update یا delete بدون محدودیت به نقش ناشناس ندهید.
- اگر کلید محرمانه افشا شد آن را لغو یا تعویض کنید. حذف از آخرین commit به معنی پاک شدن تاریخچه و نسخه‌های کپی‌شده نیست.

## محدودیت شمارنده

عدد بر اساس شناسه تصادفی مرورگر در هر روز UTC محاسبه می‌شود؛ شمارش قطعی انسان‌ها نیست. بازدیدکننده می‌تواند حافظه مرورگر را پاک کند یا درخواست خودکار بسازد. محدودیت نرخ، سوءاستفاده ساده را کاهش می‌دهد اما جلوی همه ربات‌ها را نمی‌گیرد. از این عدد برای امنیت یا صورتحساب استفاده نکنید.

## تفاوت سایت عمومی و مخزن خصوصی

سایت عمومی HTML، CSS و JavaScript را به مرورگر می‌فرستد و بازدیدکننده می‌تواند آن‌ها را بررسی کند. مخزن خصوصی تاریخچه Git و فایل‌های اصلی مخزن را از افراد بیرون مخفی می‌کند، اما کد تحویل‌شده به مرورگر را محرمانه نمی‌کند.

در GitHub Free برای حساب‌های شخصی، GitHub Pages به مخزن عمومی نیاز دارد. خصوصی کردن آن مخزن، انتشار Pages را متوقف می‌کند. برخی پلن‌های پولی انتشار از مخزن خصوصی را پشتیبانی می‌کنند اما فایل‌های سایت عمومی همچنان در دسترس هستند. در پلن رایگان، سورس را در مخزن خصوصی نگه دارید و فقط خروجی سایت را به مخزن انتشار عمومی جداگانه منتقل کنید یا از میزبان دیگری استفاده کنید.

## چک‌لیست انتشار

- [ ] هیچ secret یا service-role در فایل مرورگر یا خروجی Pages نیست.
- [ ] RLS فعال است و نوشتن مستقیم ناشناس مسدود شده است.
- [ ] URL پروژه، مبدأ سایت و کلید publishable متعلق به پروژه خودتان هستند.
- [ ] هر دو زبان، لینک‌ها، موبایل، صفحه‌کلید و خروجی چاپ بررسی شده‌اند.
- [ ] در صورت فعال بودن شمارنده، درخواست معمول پاسخ ok: true و عدد شمارنده می‌دهد.
- [ ] آخرین انتشار GitHub Actions موفق است.
