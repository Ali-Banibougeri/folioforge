# ۰۵ — امنیت، Supabase و انتشار

[← راهنمای اصلی](../../README.fa.md) · [English](../en/05-security-publishing.md)

## میزبانی رزومه ایستا

رزومه را می‌توان با HTML، CSS، JavaScript و تصویر منتشر کرد. این بخش به دیتابیس یا کلید محرمانه نیاز ندارد. GitHub Pages فایل‌های ایستا را ارائه می‌کند و تابع Supabase Edge را اجرا نمی‌کند.

گردش‌کار .github/workflows/deploy-pages.yml فقط starter/site را منتشر می‌کند. راهنمای راه‌اندازی و سورس تابع سرور را خارج از خروجی عمومی نگه دارید.

## راه‌اندازی GitHub Pages

۱. مخزن را در GitHub قرار دهید.
۲. به Settings → Pages بروید.
۳. GitHub Actions را به عنوان منبع انتخاب کنید.
۴. یک تغییر به main ارسال کنید یا گردش‌کار را دستی اجرا کنید.
۵. آدرسی را که گردش‌کار گزارش می‌کند باز کنید.

پس از تغییر فایل‌ها، آخرین اجرای workflow را بررسی کنید؛ موفقیت commit به معنی موفقیت انتشار نیست. در سایت پروژه‌ای، مسیرهای نسبی مهم‌اند چون URL عمومی ممکن است نام مخزن را هم در مسیر داشته باشد.

## قابلیت‌های اختیاری Supabase

رکورد مشترک و شمارنده بازدید از Supabase استفاده می‌کنند. برای فعال‌سازی:
۱. پروژه Supabase خودتان را ایجاد کنید.
۲. فایل starter/backend/arcade-schema.sql را در SQL Editor اجرا کنید.
۳. URL پروژه و کلید publishable را در starter/site/assets/site-config.js تنظیم کنید.
۴. CLI را به پروژه خود وصل کنید و از starter/backend/config.toml به عنوان نمونه استفاده کنید.
۵. تابع arcade-api را از starter/backend/functions/arcade-api/index.ts منتشر کنید.
۶. ARCADE_SITE_ORIGIN را برابر مبدأ واقعی سایت عمومی قرار دهید و یک مقدار تصادفی طولانی برای ARCADE_RATE_SALT تعیین کنید.
۷. یک دور کامل بازی کنید و لاگ‌ها و وضعیت دیتابیس را بررسی کنید.

شناسه پروژه Supabase و مبدأ سایت باید با مقدارهای خودتان جایگزین شوند. کلید محرمانه سرور شخص دیگری را استفاده نکنید. کد به طور پیش‌فرض از کلید محرمانه داخلی Supabase استفاده می‌کند و امکان override فقط-سرور نیز دارد. مقدار secret را در README، چت، تصویر یا سورس قرار ندهید.

## امنیت دیتابیس

- RLS را روی جدول‌های در معرض API فعال نگه دارید.
- مجوز بدون محدودیت insert/update/delete به کاربران ناشناس ندهید.
- از حداقل سطح دسترسی استفاده کنید.
- ورودی‌ها را اعتبارسنجی و حجم درخواست‌ها را محدود کنید.
- ورودی مرورگر را غیرقابل‌اعتماد بدانید.
- کلید secret یا service-role را به مرورگر نفرستید.
- IP هش‌شده یا شناسه بازدید را ناشناس‌سازی کامل فرض نکنید؛ هش‌ها نیز می‌توانند ملاحظات حریم خصوصی داشته باشند.

## تفاوت سایت عمومی و سورس خصوصی

سایت عمومی باید HTML، CSS و JavaScript را به مرورگر بفرستد؛ بنابراین بازدیدکننده می‌تواند آن‌ها را بررسی کند. مخزن خصوصی تاریخچه Git و فایل‌های سورس اصلی را از افراد بیرون مخفی می‌کند، اما کد تحویل‌شده به مرورگر را محرمانه نمی‌کند.

در GitHub Free برای حساب‌های شخصی، GitHub Pages به مخزن عمومی نیاز دارد. خصوصی کردن مخزن سایت کاربری، انتشار Pages را متوقف می‌کند. پلن پولی ممکن است انتشار از مخزن خصوصی را پشتیبانی کند، اما سایت منتشرشده همچنان عمومی است مگر دسترسی خود سایت هم محدود شده باشد.

برای داشتن سایت عمومی و سورس خصوصی در پلن رایگان، یک مخزن خصوصی برای سورس و مخزن عمومی جدا برای خروجی انتشار بسازید یا از میزبان ایستای دیگری استفاده کنید. منطق حساس و تمام کلیدهای محرمانه باید در سرور باشند.

## چک‌لیست انتشار

- [ ] کلید secret یا service-role در فایل مرورگر یا خروجی Pages نیست.
- [ ] RLS روشن است و نوشتن ناشناس محدود شده است.
- [ ] URL، مبدأ و کلید عمومی مربوط به پروژه خودتان هستند.
- [ ] هر دو زبان و لینک‌ها درست کار می‌کنند.
- [ ] دسکتاپ، موبایل، صفحه‌کلید و چاپ بررسی شده‌اند.
- [ ] اگر آرکید فعال است، یک دور کامل از هر بازی انجام شده است.
- [ ] فقط بعد از پاسخ موفق سرور، رکورد مشترک تأییدشده اعلام شده است.
- [ ] جدیدترین انتشار GitHub Actions موفق شده است.
