# FolioForge
### داستان حرفه‌ای خودت را به یک وب‌سایت رزومه تبدیل کن.

**یک کیت آماده و دوزبانه برای ساخت رزومه آنلاین حرفه‌ای با کمک هوش مصنوعی؛ همراه با چهار بازی آرکید اختیاری.** این پروژه برای کسانی طراحی شده که برنامه‌نویس نیستند و همچنین توسعه‌دهندگانی که به یک روند کاری منظم و قابل تکرار نیاز دارند.

## در چند دقیقه شروع کن

برای استفاده از این پروژه لازم نیست برنامه‌نویس باشی. رزومه واقعی خودت و یک نسخه از این مخزن کافی است.

**ساده‌ترین روش با کمک هوش مصنوعی**

۱. این مخزن را دانلود یا Clone کن.

۲. پوشه پروژه را در محیط کدنویسی هوش مصنوعی باز کن و رزومه خودت را به‌صورت PDF، DOCX یا متن پیوست کن.

۳. دستور زیر را در ChatGPT، Codex یا عامل کدنویسی‌ای که اجازه ویرایش فایل‌های پروژه را دارد وارد کن.

۴. نتیجه را مرور کن، تست‌ها را اجرا کن و بعد سایت را منتشر کن.

> **این دستور را کپی کن**
>
> فایل‌های AGENTS.md و README.md را کامل بخوان و از AGENTS.md پیروی کن. رزومه پیوست‌شده را منبع حقیقت قرار بده. وب‌سایت داخل starter/site/ را متناسب با مسیر شغلی من شخصی‌سازی کن؛ محتوای واقعی فارسی و انگلیسی بنویس؛ هویت بصری را متناسب با حوزه حرفه‌ای من انتخاب کن؛ بازی‌های اختیاری را سالم نگه دار؛ دستور node scripts/check.mjs را اجرا کن و تمام ایرادهایی را که می‌توانی رفع کن. فقط مواردی را گزارش کن که امکان بررسی آن‌ها را نداشتی. سؤال غیرضروری نپرس، اطلاعات را نساز و وقتی می‌توانی خودت فایل کد را تغییر بدهی از من نخواه دستی کدنویسی کنم.

فایل AGENTS.md دستورالعمل دقیق و تکرارپذیر عامل کدنویسی را مشخص کرده است. هدف این است که عامل واقعاً سایت را پیاده‌سازی کند، نه اینکه فقط آموزش یا یک ماکاپ ارائه دهد.

## چطور شخصی‌سازی‌اش کنم؟

عامل هوش مصنوعی باید رزومه تو را تحلیل کند و محتوای سایت و طراحی را متناسب با آن تغییر دهد. فایل اصلی برای ویرایش محتوای رزومه:

**starter/site/assets/portfolio-data.js**

این فایل پروفایل، خلاصه حرفه‌ای، تجربه‌ها، تحصیلات، پروژه‌ها، مهارت‌ها، اطلاعات تماس، برچسب‌های دوزبانه و رنگ‌های تم را نگه می‌دارد. برای بیشتر تغییرات رزومه، اولین محل ویرایش همین فایل است؛ در صورت نیاز عامل می‌تواند styles.css و HTML را نیز تغییر دهد.

قالب نمونه را بدون تغییر منتشر نکن. تمام نام‌ها، لینک‌ها و placeholderها باید با اطلاعات واقعی جایگزین شوند. بخش‌هایی را که مناسب تو نیستند حذف کن.

## انتشار وب‌سایت

این پروژه گردش‌کار GitHub Pages دارد. پس از بارگذاری فایل‌های شخصی‌سازی‌شده:

۱. در مخزن GitHub به **Settings → Pages** برو.

۲. روش ساخت و انتشار را روی **GitHub Actions** قرار بده.

۳. یک تغییر به شاخه main ارسال کن یا گردش‌کار را از قسمت Actions اجرا کن.

۴. آدرس منتشرشده را باز کن و سایت را در یک پنجره خصوصی مرورگر آزمایش کن.

این مجوز Pages یک‌بار باید در GitHub فعال شود. عامل می‌تواند کد و گردش‌کار را آماده کند، اما بدون مجوز حساب تو نمی‌تواند تنظیمات دسترسی مخزن را تغییر دهد.

## رکورد مشترک آرکید اختیاری است

صفحه رزومه ایستا است و به دیتابیس نیاز ندارد. Supabase فقط برای شمارنده مشترک و جدول رکورد مشترک لازم است؛ بازی‌ها بدون آن هم با رکورد محلی قابل استفاده‌اند.

- [راهنمای تنظیم بک‌اند و Supabase](./docs/fa/05-security-publishing.md)
- [راهنمای انگلیسی](./docs/en/05-security-publishing.md)
- [نکات امنیتی](./SECURITY.md)

کلید secret یا service-role را در JavaScript مرورگر، HTML، مخزن عمومی یا پرامپت قرار نده. کلید publishable با کلید محرمانه متفاوت است و همچنان به مجوز محدود دیتابیس و Row Level Security نیاز دارد.

## پیش از انتشار بررسی کن

اگر Node.js نصب است، در پوشه مخزن این دستور را اجرا کن:

    node scripts/check.mjs

این اسکریپت یک کنترل سریع است، نه تست کامل مرورگر یا ممیزی امنیتی. سایت زنده را در موبایل و دسکتاپ، به هر دو زبان بررسی کن و حداقل یک دور از هر بازی را تا پایان انجام بده. درباره قابلیت‌هایی که واقعاً تست نشده‌اند ادعای موفقیت نکن.

## حریم خصوصی و استفاده مجدد

این پروژه یک قالب آموزشی قابل استفاده مجدد است؛ نباید رزومه، عکس، ایمیل شخصی، لینک خصوصی یا کلید API شخص دیگری داخل آن باشد. محتوای شخصی قالب عمداً عمومی و نمونه‌ای است؛ پیش از انتشار آن را جایگزین کن. مجوز LICENSE و محدودیت‌های استفاده را نیز بخوان.
