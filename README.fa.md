# FolioForge
### داستان حرفه‌ای خودت را به یک وب‌سایت شخصی تبدیل کن.

**یک کیت آماده و دوزبانه برای ساخت رزومه آنلاین حرفه‌ای با کمک هوش مصنوعی.** این پروژه برای کسانی طراحی شده که برنامه‌نویس نیستند و همچنین توسعه‌دهندگانی که به روند کاری منظم و قابل تکرار نیاز دارند.

## در چند دقیقه شروع کن

برای استفاده از این پروژه لازم نیست برنامه‌نویس باشی. رزومه واقعی خودت و یک نسخه از این مخزن کافی است.

۱. در GitHub حساب بساز یا وارد حساب خودت شو و یک نسخه مستقل از این مخزن ایجاد کن.

۲. پوشه پروژه را در محیط کدنویسی هوش مصنوعی که اجازه ویرایش فایل‌ها دارد باز کن و رزومه را به‌صورت PDF، DOCX یا متن پیوست کن.

۳. دستور آماده زیر را به ChatGPT، Codex یا عامل کدنویسی‌ای که مجوز ویرایش فایل‌ها دارد بده.

۴. عامل باید سایت را شخصی‌سازی کند، تست‌ها را اجرا کند و فقط کارهایی را گزارش کند که به اتصال حساب یا اقدام دستی تو نیاز دارند.

> **این دستور را کپی کن**
>
> فایل‌های AGENTS.md و README.md را کامل بخوان و از AGENTS.md پیروی کن. رزومه پیوست‌شده را منبع حقیقت قرار بده. سایت داخل starter/site/ را متناسب با مسیر شغلی و مخاطب من شخصی‌سازی کن، محتوای واقعی فارسی و انگلیسی بنویس، هویت بصری را متناسب با حوزه من انتخاب کن و فقط شمارنده بازدید اختیاری را حفظ کن. دستور node scripts/check.mjs را اجرا و هر ایرادی را که می‌توانی رفع کن. سؤال غیرضروری نپرس، اطلاعات را نساز و وقتی می‌توانی کد را خودت تغییر بدهی از من نخواه دستی ویرایش کنم. پیش از هر کاری که به حساب خارجی یا مجوز نیاز دارد، به من بگو کدام سرویس لازم است، لینک مستقیم ساخت حساب یا اتصال را بده و مراحل دقیق را توضیح بده؛ سپس همه کارهایی را که به آن اتصال وابسته نیستند ادامه بده. هرگز رمز یا کلید محرمانه را در چت از من نخواه.

فایل AGENTS.md قرارداد کاری مشخصی برای عامل کدنویسی است: باید سایت را واقعاً پیاده‌سازی کند، نه اینکه فقط راهنما یا ماکاپ بدهد.

## چطور شخصی‌سازی‌اش کنم؟

عامل هوش مصنوعی باید رزومه را تحلیل کند و محتوای سایت و طراحی را متناسب با آن تغییر دهد. فایل اصلی برای ویرایش اطلاعات رزومه:

**starter/site/assets/portfolio-data.js**

این فایل پروفایل، خلاصه، تجربه، تحصیلات، پروژه‌ها، مهارت‌ها، اطلاعات تماس، برچسب‌های دوزبانه و رنگ‌های تم را نگه می‌دارد. برای بیشتر تغییرات رزومه، ابتدا همین فایل را ویرایش کن؛ عامل در صورت نیاز می‌تواند styles.css و HTML را هم تغییر دهد.

قالب نمونه را بدون ویرایش منتشر نکن. نام‌ها، تاریخ‌ها و لینک‌ها باید با اطلاعات واقعی جایگزین شوند. بخش‌هایی را که مناسب مسیر کاری تو نیستند حذف کن.

## اتصال حساب‌ها: فقط وقتی لازم است

صفحه رزومه یک سایت ایستا است و برای نمایش خود به دیتابیس نیاز ندارد.

- **حساب GitHub:** برای نگهداری پروژه و انتشار با GitHub Pages لازم است.
- **ابزار کدنویسی هوش مصنوعی با دسترسی فایل:** اگر می‌خواهی عامل مستقیماً نسخه محلی را ویرایش کند لازم است. از پنجره رسمی ورود/اتصال همان ابزار استفاده کن.
- **حساب Supabase:** اختیاری است و فقط برای شمارنده بازدید مشترک لازم است.

اگر اتصالی وجود نداشته باشد، عامل باید سرویس موردنیاز را مشخص کند، لینک رسمی ساخت حساب را بدهد و حداقل مجوز موردنیاز را توضیح دهد؛ در همین حین کارهای غیرمرتبط را متوقف نکند. رمز، توکن GitHub، کلید secret یا service-role را در چت ارسال نکن.

راهنما: [۰۴ — اتصال حساب‌ها و سرویس‌ها](./docs/fa/04-connect-services.md).

## انتشار وب‌سایت

این مخزن گردش‌کار GitHub Actions دارد که فقط starter/site را منتشر می‌کند. پس از آماده‌سازی:

۱. در مخزن شخصی خودت به Settings → Pages برو.

۲. GitHub Actions را به عنوان منبع انتشار انتخاب کن.

۳. به شاخه main تغییر ارسال کن یا گردش‌کار را در Actions اجرا کن.

۴. آدرس منتشرشده را باز کن و نمایش موبایل و دسکتاپ را بررسی کن.

این مجوز یک‌بار باید در GitHub تنظیم شود. گردش‌کار با push فقط تست‌ها را اجرا می‌کند. برای انتشار، ابتدا در Settings → Pages گزینه GitHub Actions را انتخاب کنید؛ سپس در Actions → Check and optionally deploy FolioForge → Run workflow، گزینه deploy را فعال و اجرا کنید. اگر Pages فعال نباشد یا مجوز کافی وجود نداشته باشد، عامل باید همین مرحله را توضیح دهد و ادعای انتشار موفق نکند.

## شمارنده بازدید اختیاری

تا وقتی پروژه Supabase خودت را تنظیم نکرده‌ای، شمارنده غیرفعال است ولی سایت رزومه همچنان کار می‌کند. برای راه‌اندازی کامل، [راهنمای شمارنده بازدید](./docs/fa/05-security-publishing.md) را ببین.

هنگام پیش‌نمایش محلی، اعلان راه‌اندازی نمایش داده می‌شود. همچنین با افزودن پارامتر ?setup=1 به آدرس می‌توانی اعلان را ببینی. بازدیدکنندگان عادی سایت عمومی این پیام را نمی‌بینند.

## امنیت و حریم خصوصی

- عدد شمارنده، شناسه مرورگر به ازای هر روز UTC است؛ شمارش قطعی انسان‌ها نیست.
- کد مرورگر عمومی و قابل بررسی است؛ اطلاعات محرمانه یا الگوریتم اختصاصی حساس را در آن نگذار.
- کلید secret و service-role فقط در اسرار سمت سرور قرار می‌گیرند.
- کلید publishable فقط در صورت محدود بودن مجوزهای دیتابیس و فعال بودن RLS باید در مرورگر استفاده شود.
- رزومه یا اطلاعات تماس خصوصی دیگران را در نمونه عمومی قرار نده.

راهنما: [SECURITY.md](./SECURITY.md).

## تست پیش از انتشار

اگر Node.js نصب است، در پوشه اصلی مخزن اجرا کن:

    node scripts/check.mjs

این اسکریپت کنترل سریع است، نه تست کامل مرورگر یا ممیزی امنیتی. هر دو زبان، لینک‌ها، خروجی چاپ، موبایل و در صورت فعال بودن، API شمارنده را آزمایش کن. فقط درباره تست‌هایی که واقعاً اجرا شده‌اند ادعای موفقیت کن.
